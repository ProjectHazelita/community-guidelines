## 术语说明

为避免下文中可能的困惑与混淆，这里需要提前说明一些术语：

**Project Hazelita** 是零音在 2024 年立项的开发项目；**Project Hazelita 社群** 是零音建立的技术社群，后者包含 QQ 群聊、Discord 服务器和 Telegram 群组。我们统称这三者为 **Hazelita Plaza**。

后文中，**Project Hazelita 社群** 可能被简称为「社群」、「本社群」等，**《Project Hazelita 社群公约》** 可能会简称为「公约」、「本公约」等。

## 简短版

Project Hazelita 社群包含 QQ 群聊、Discord 服务器和 Telegram 群组，三者统称 **Hazelita Plaza**。这里兼具项目技术交流与生活支持两方面的定位：欢迎讨论项目、分享知识，也允许日常闲聊、倾诉与互相支持。

加入或继续留在社群，即表示你知悉并同意遵守本公约；未完整阅读长版文本，不免除遵守义务。以下是本公约的共同底线：

- **尊重成员**：保护成员的身份、称呼、经历与边界，不得羞辱、贬低、否认、标签化、恶意追问或排斥；不得骚扰、持续攻击、开盒、威胁或恶意外传。
- **高冲突议题**：公共政策、意识形态、身份政治、宗教争端等辩论不在群内展开；管理团队叫停后应当停止。
- **隐私**：未经允许不得公开、传播或利用他人的隐私信息；不得导出、上传或把群聊记录用于训练模型等用途。
- **意见表达**：可以批评作品、项目、观点与具体行为，但不得贬低人格、跟风围攻，或在叫停后持续纠缠。
- **倾诉与支持**：可以分享困难、请求支持，但支持出于自愿，不回应不构成过错；不得刷屏、施压，或以伤害、退出威胁迫使他人回应。
- **危机求助**：求助本身不是违规；出现具体、迫近的人身安全风险时，优先转向现实帮助，而不是在群内围观。
- **一视同仁**：贡献、资历、熟人关系与管理团队身份均不构成违规豁免。
- **管理权限**：只用于维护社群，不得用于玩笑、私人互动或表达个人不满。

违规时，管理团队可以提醒、撤回、禁言、移出群聊或拒绝入群；处理应有事实依据并留下记录。紧急情况下可以先采取措施止损，事后说明并留痕；成员对处理可以申诉，最多两次。

## 愿景

我们希望 Project Hazelita 社群成为一个 **友善、包容、全性别友好、尊重多样性** 的技术社群。这里欢迎各种各样的朋友，无论你是开发者、用户、学者，还是偶然抵达的旅人。我们希望各位在这里能够交流技术、分享知识，也能在合适的空间里谈论生活、互相支持。

我们发布该公约，并非规训群友、亦非赋予管理团队不受约束的权力。公约的目的是划清底线、减少冲突扩散、保护成员与项目，并让管理行为有据可依。

我们允许脆弱、允许学习、允许成员的不成熟；但我们并不包容对他人持续占用、施压、伤害等的行为。我们欢迎各位将这里视为重要的归属，但这里也并不能承担任何人的全部需求。管理团队可以依据可观察的行为评价成员的接纳度与风险值，而并非出于人与人之间的相互猜忌。

## 适用范围与社群结构

本公约适用于 Project Hazelita 在各个平台的社群，包括 QQ 群聊、Discord 服务器和 Telegram 群组。

Project Hazelita 社群欢迎对 Project Hazelita 本身或其衍生项目、技术与生活分享感兴趣的朋友。成员可以经邀请加入、或完成入群问题后经审核加入。成员可以在 Project Hazelita 社群自行选择参与的话题与活动。一般情况下，我们不会经常清理不活跃的成员；同时，也不要求成员表达同等的归属、热情与感激。

## 共同底线

### 尊重成员与身份表达

成员有权表达自己的身份、称呼、偏好、经历与生活状态。社群保护成员的身份表达，包括但不限于性别、性取向、神经多样性、身体状况、地域、家庭背景、经济状况、教育经历等的内容。不得因为上述身份或特征，羞辱、贬低、否认、标签化、恶意追问或排斥成员；我们也并不欢迎将成员的存在视为潜在问题的表达，即使这些表达言语上客观中立。

成员可以保留个人的观点，但我们禁止否认、质疑其他成员的存在、身份或基本尊严的言论。

### 高冲突议题

出于对社群的综合考量，社群不允许发起或延续关于公共政策、意识形态、身份政治、宗教争端等高冲突的辩论。管理团队应当叫停相关话题，并要求成员转向私聊、专门讨论空间等。这并非禁止成员表达自己的身份或阐述自己的遭遇，也并非禁止对明显的冒犯进行澄清，而是禁止将群聊转为这些议题的辩论场。

### 骚扰、持续攻击与边界

成员不得在群内骚扰他人、持续攻击他人或侵犯他人的边界。这包括：

- 在对方明确要求停止后仍然持续关注、追问、调侃或提及冒犯性内容；
- 反复讽刺、影射、标签化、提及群成员，或通过起哄等方式持续攻击特定成员；
- 以开玩笑、说话风格、本质关心等的理由，持续侵犯成员明确表达的边界。

单次表达不当未必构成骚扰，但若在提醒后继续或形成稳定的攻击模式，则应按违规处理。

### 意见表达

成员可以对公开分享的作品、项目、观点或具体行为等表达不同意见，包括直接、具体的负面评价；但这样的评价必须针对可说明的内容或事实，不得将这些问题泛化为对对方人格、身份或价值的嘲讽与羞辱。即，针对对方作品、项目、观点或具体行为等指出意见，不等同于对对方的直接嘲讽与攻击。

我们禁止以年龄、学历、资历、工具使用方式等贬低其他成员，也同样禁止年长或有经验者以居高临下的态度羞辱他人。同时，初学者和年轻的成员可以选择是否接受解释与引导，但仍然需要遵守同样的行为底线。我们禁止以这些问题反复嘲讽、跟风围攻、跨话题影射或持续纠缠他人。

### 隐私与外传

成员不得未经允许公开、传播或利用他人的隐私信息，包括但不限于真实姓名、联系方式、住址、照片、学校或单位、家庭情况、医疗或心理状况、私人聊天记录等。社群并非严格保密的空间，成员之间可以分享有趣的公开聊天片段，但这些片段不能：

- 包含涉及个人隐私、敏感经历等其他不宜公开的内容；
- 断章取义地传播社群内容，造成误解、围攻或名誉损害；
- 恶意传播聊天记录，造谣、挂人或引导外部争端。

### 外部冲突与外部行为

社群并不负责裁决外部冲突。但当外部行为与社群的安全或秩序有明确关联时，管理团队可以介入。例如：

- 外部事件的当事人包含社群成员，且伤害、骚扰、争吵或压力正在延伸到社群；
- 成员试图将社群作为外部争端的延伸讨论处；
- 外部行为已经显示部分成员存在开盒、骚扰、攻击、煽动围攻、滥用权限等底线风险；
- 这些行为已经让社群成员担心自己交流的安全性；
- 成员的加入或存在会让社群承担明显的冲突扩散风险。

需要注意的是，成员不会因为不受欢迎被处罚。但若管理团队基于截图、可靠的聊天记录或多位成员的阐述，合理确认其存在明确的社群风险，则可以拒绝其入群、限制其发言或移出社群。同时，入群的审核应当比留群的处罚更加严格。拒绝入群并不等同于我们否定申请者或为其定罪；同时，移出现有成员则必须有更明确的事实依据，并做好记录。

Project Hazelita 不负责裁判所有外部社群的争端。但当外部行为与 Hazelita 成员安全或社群秩序存在明确关联时，管理团队可以介入。

### 违法、危险与明显有害内容

成员不得发布、传播或引导他人获取违法、明显危险、露骨色情、赌博、毒品、恐怖暴力、开盒或恶意攻击工具、诈骗信息，或其他会使社群与成员承担明显风险的内容。

成员不得实施、威胁实施或煽动针对他人的暴力、骚扰、围攻或其他伤害行为。不得鼓励、煽动或美化自伤，不得在群内传播便于模仿的自伤方法、危险过程直播或刺激性影像。表达自己有自伤念头、说明已经发生的伤害以请求帮助，并不能因其内容本身视为违规；但涉及安全风险时，应当按照 [危机求助与现实支持](#危机求助与现实支持) 一节的内容优先转向现实帮助。

## 社群的通用规则

Project Hazelita 社群兼具项目技术交流与生活支持两方面的定位。项目与技术话题包括：

- Project Hazelita 及相关项目的开发、使用、反馈与建议。
- 计算机技术、开源协作、学科问题、学习经验与工具讨论。
- 与项目成员协作有关的必要沟通。

这里也允许成员分享日常、兴趣、创作、情绪与闲聊。不同话题共享群聊空间，不应长期由同一成员或同一争论独占。

### 讨论分歧与降温

当讨论出现分歧时，应当先由各方澄清讨论对象、适用范围与实际意思，以免因措辞不清互相认定为恶意。讨论具体事件时，应当区分亲身经历、可核实的信息与自己的假设。当讨论偏题、陷入循环争执或进入围攻时，管理团队应当明确议题、提醒停止循环和争执，或直接暂停话题，不必等待双方争出胜负。成员应当遵守叫停要求。

### 倾诉与支持边界

成员可以在社群分享困难、倾诉与请求支持，其他成员也可以在自愿的情况下提供安慰、支持、建议与陪伴，但同时也可以选择不回应，拒绝或停止支持。倾诉与支持应当尊重他人的时间、意愿和承受能力，即：

- 不得将社群作为转移外部争吵、围攻他人或宣泄敌意的场所；
- 不得因为回应不足而责怪其他成员；
- 不得长期要求他人持续安抚、随时在线，或通过刷屏、反复点名等的方式强迫他人参与讨论；
- 不得以自伤、崩溃表达或退出威胁等迫使他人回应、改变决定或承担责任。

当倾诉持续占用大量群聊空间、影响其他讨论或造成了压力时，管理团队可以提醒暂停，并在必要时限制相关讨论。处理应当依据具体行为、影响与提醒后的表现；涉及现实安全风险时，按照 [危机求助与现实支持](#危机求助与现实支持) 一节的内容处理。

### 危机求助与现实支持

社群并非专业的心理危机干预场所，不能替代现实支持、医疗帮助或紧急救援。所有成员均不承担全天候在线、持续监护或保障救援的职责。表达心理困难或危机求助本身不属于违规行为，但也不免除对具体越界行为的处理。出现具体、迫近的自伤风险、已经受伤或正在遭受伤害或暴力时，采取下面的措施：

- 鼓励当事人立刻联系当地急救、警方或就近的医疗机构，可能时提供必要协助，不应以社群的安慰代替紧急处理。
- 尽可能由几个可靠的成员负责联络、协助寻找现实支持。其他成员不应参与起哄、复读、激将法等。
- 联系对方安全、可信任的现实支持者。
- 必要时停止当事人在群内的危险内容传播等。

需要注意的是，在当事人的家庭、校园等可能是伤害来源时，应当尽量避免其再次暴露于风险的可能性。危机后，当事人是否留存群聊以及处理决定，应当依据具体行为、影响、可能持续的越界或伤害行为等，遵循管理流程与复核要求裁决。不能仅因为成员的心理疾病、接受治疗、求助等而给予处罚；也不能因为其处于危机状况而无限豁免其越界行为。

成员可以分享热线、机构等的体验，也可以讨论具体服务的专业性与隐私风险，但应当区分个人经历与一般结论，也不应以此阻止其他成员获得专业的援助。

## 管理与处理流程

### 管理原则

管理团队的职责是维护社群秩序、成员边界与社群的长期健康，其管理行为不应以审判成员的人格为目的。

管理团队应遵循以下原则：

- 对于明显冲突、骚扰、隐私泄露、外部争端转移等情况，应优先停止伤害和扩散。
- 处理措施应参考行为风险、严重程度、持续性和既往情况。
- 除紧急止损外，处理应尽量基于截图、聊天记录、多名成员说明等管理团队可见的事实。
- 贡献、资历、关系亲近、管理团队身份等均不构成减轻或免除理由。
- 公告应让成员知晓事件缘由和处理原因，但不应公开不必要的隐私细节。

### 管理团队约束

管理团队不得将撤回、禁言、移出群聊等权限用于玩笑、私人互动或表达个人不满的情形。管理员滥用权限的，第一次提醒并记录；重复发生或造成明显后果的，应撤销其管理权限。

管理员选拔由零音负责。管理团队可以基于信任关系、在线情况、沟通能力和维护社群边界的能力选择管理员，但管理员身份不是资历奖励，也不是社群地位；不适合继续维护边界时，应撤销权限。管理员本人是冲突当事人、被投诉对象、明显利益相关者时，应回避该事件处理，由其他非涉事管理员处理或复核。

### 处理措施

管理团队可以根据情况采取以下措施：

- 提醒：指出问题并要求停止。
- 撤回：撤回明显不当、引战、侵犯隐私或正在扩散冲突的消息。
- 禁言：用于冷却冲突、防止继续伤害或等待复核。
- 移出群聊：用于严重违规、具有明确社群风险、外部冲突转移或多次提醒无效的情况。
- 拒绝入群：用于入群风险明显高于社群可承受范围的情况。

一般情况下，第一次轻微问题以提醒为主；提醒后再次发生，可以禁言或采取更强措施。明显严重的隐私泄露、针对他人的威胁、骚扰、外部冲突转移、持续攻击或危险内容传播，可以先撤回、禁言或移出，再补充说明和复核。涉及人身安全时，应同时遵循 [危机求助与现实支持](#危机求助与现实支持) 一节的流程，不得把危机求助本身当作处罚依据。

需要注意的是，禁言与移出并非以羞辱为目的，同时也不要求成员表演式道歉，而是为了快速止损、保护受影响的成员、阻止冲突扩散并维护社群边界。

### 重大处理与留痕

移出成员、长时间禁言、拒绝入群、撤销管理权限等任何可能引起明显争议的处理属于重大处理。在非紧急情况下，重大处理应当由至少两名非涉事管理员同意；在紧急情况下，管理员可以先采取必要措施，再于事后说明并留痕，以便后续管理团队复核。面向成员的公告应当简洁、克制、可理解，不应以公开审判书的风格起草，也不应暴露无关隐私。

### 复核与投诉

成员可以对处理提出申诉。申诉最多两次：

- 第一次由原处理人核查并说明。
- 第二次由其他非涉事管理员核查。

复核成员的申诉时，管理团队应关注事实是否充分、条款是否适用、措施是否过重或过轻、是否存在利益相关或情绪执法。两次复核均应留痕。成员可以投诉管理员的滥权、偏袒、情绪执法或违反回避规则，同时，被投诉管理员应回避相关处理。

## 隐私与数据使用

群聊记录默认只用于群聊本身、管理处理、必要复核和管理团队制作的去标识化统计。

除非获得相关成员明确同意，成员不得主动导出、上传、外部分析、训练模型或公开发布群聊记录。不得将群聊记录用于生成式对话模型训练、角色扮演数据、商业用途或任何可能伤害成员的用途。

紧急救援是上述隐私保护与群聊记录使用限制的必要例外：为应对具体、迫近的人身安全风险，可以向急救、警方、医疗人员或安全可信任的现实支持者提供救援必需的信息。在可行时应先征求当事人同意；紧急情况下，披露应限于救援必需的对象与内容，不得借此在群内或公开渠道传播隐私。相关披露应留下简要记录，供必要复核。

QQ 内置的 AI 总结、搜索、风控等的平台功能可能不完全受 Project Hazelita、社群和管理团队控制。管理团队会尽量提醒成员相关风险，但不对第三方平台的数据处理行为作出担保。

管理团队对群聊内容的分析，如制作互动报告等，应使用去标识化统计，不展示敏感信息，不把具体发言和具体成员绑定，除非该发言本身公开、非敏感，且已获得必要同意或属于处理违规所必需。

## 附录

### 刷屏

刷屏的判断取决于内容、频率和上下文。以下行为可能被视为刷屏：

- 短时间内连续发送大量缺乏实质内容的消息。
- 在其他成员明显没有参与兴趣时，持续独占话题空间。
- 大量复读、跟风、表情包或无意义字符，打断正常讨论。

实质性讨论通常不会被视为刷屏。分享多张截图或多段相关内容时，建议使用合并转发或整理后发送。

### 推广说明

社群允许分享非商业性质的项目、活动、工具和学习资源等，同时也支持在社群内宣传自己的群聊，但必须控制频率以避免打断正常的讨论。对于以营利为目的的广告或商业内容，必须先行询问管理团队，并在管理团队的要求下公开发布。社群不对推广内容的质量和性质做保证；但若推广内容有明显的质量问题、或有多位成员反映、或被确认为不适宜公开或传播的内容，管理团队有权禁止这些内容的推广。

### 更新

本公约会随着社群实际需要更新。重要更新应在社群中提示成员，并尽可能提供简短说明。
